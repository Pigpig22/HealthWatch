# HealthWatch 技术架构

本文说明 HealthWatch 的模块边界、数据流与当前实现约束，便于联调 ESP32、定位问题和继续扩展。

## 总览

```text
┌──────────────────────┐
│ ESP32 / ESP32-S3     │
│ 传感器 + NimBLE      │
└──────────┬───────────┘
           │ BLE Notify
           ▼
┌──────────────────────┐
│ pages/home/home.vue  │
│ 扫描、连接、订阅、解析 │
└───────┬───────┬──────┘
        │       │
        │       └──────────────┐
        ▼                      ▼
实时指标卡片              紧急消息处理
        │                振动 → 确认 → 拨号
        │ uni.$emit
        ▼
┌──────────────────────┐
│ pages/data/data.vue  │
│ 趋势图、统计、历史、导出 │
└──────────────────────┘
```

## 核心模块

### 1. BLE 连接层

主页负责：

- 初始化系统蓝牙适配器；
- 扫描并筛选名称包含 `ESP32_BLE` 的设备；
- 根据 RSSI 展示信号强度；
- 建立 BLE 连接并发现服务、特征值；
- 为健康数据和消息特征值启用 Notify；
- 断开时清理监听器和页面状态。

BLE 常量集中在 `pages/home/home.vue` 的 `ESP32_CONFIG` 中。硬件端和 App 端必须保持一致。

### 2. 数据解析层

健康数据通知支持：

- JSON：`{"temp":36.5,"heart":75,"steps":1234,"spo2":98}`
- 逗号分隔：`75,1234,36.5,98`

解析成功后会：

1. 更新主页指标；
2. 通过 `uni.$emit('healthDataUpdate', data)` 通知数据页；
3. 将最近一次完整读数写入 `globalHealthData` 本地存储。

### 3. 可视化层

数据页按体温、心率、步数和血氧分别维护采样序列：

- 每项最多保留最近 50 个采样点；
- 自动计算最大值、最小值和平均值；
- 根据实际数据范围生成自适应 Y 轴；
- 使用 uni-app Canvas API 绘制面积折线图；
- 相同数据在 1 秒内会被去重。

当前序列保存在页面运行内存中，不是长期历史数据库。

### 4. 紧急联系人

联系人保存在本地键 `health_contacts`。当消息特征值收到内容时：

1. 更新最近消息和接收时间；
2. 触发短振动；
3. 选择第一个有效联系人；
4. 显示确认弹窗；
5. 用户确认后调用 `uni.makePhoneCall`。

为了防止误拨，当前实现不会绕过用户确认直接呼叫。

### 5. 数据导出

数据页将当前选中指标的记录整理为 CSV 文本，并写入系统剪贴板。该行为不是生成文件，也不会自动上传。

## 本地状态

| 数据 | 存储方式 | 生命周期 |
| --- | --- | --- |
| 紧急联系人 | `uni.setStorageSync` | 持久化在本机，直到清除应用数据 |
| 最近一次健康读数 | `uni.setStorageSync` | 本地持久化，用于页面恢复 |
| 趋势采样点 | Vue 内存状态 | 页面/应用运行期间，每项最多 50 条 |
| 导出数据 | 系统剪贴板 | 由操作系统管理 |

## 权限边界

Android 配置包含 BLE、定位和电话相关权限。不同 Android 版本对附近设备权限的要求可能不同，发布正式版本前应：

- 只保留功能实际使用的权限；
- 为权限用途提供清楚说明；
- 测试拒绝权限、蓝牙关闭和设备离线场景；
- 避免在日志中打印敏感健康数据或真实电话号码。

## 扩展建议

1. 抽离 BLE 服务层，降低页面组件复杂度。
2. 引入 Pinia 或独立状态模块管理跨页数据。
3. 使用 SQLite/本地文件实现长期历史记录。
4. 增加自动重连、超时和数据包校验。
5. 为解析器、统计逻辑和协议兼容性补充单元测试。
6. 为不同设备型号增加可配置的 UUID 和指标映射。
